#+TITLE: Delegated Agent Fanout and Shared Budget
#+OPTIONS: toc:nil

* Research case and exact boundary

[[https://arxiv.org/html/2608.15888][Bounded Agents (2026)]] requires
cumulative budget accounting across delegation hops and states that its
composition result assumes serialized admission. Its limitations identify
attacks spanning multiple sessions as residual risk requiring durable lineage
state. A [[https://arxiv.org/abs/2609.15906][September 2026 survey of agent
authorization]] independently identifies runtime enforcement and
aggregation bounds as unresolved architecture gaps. The survey is a map of
the literature; this example does not treat it as experimental evidence.

[[https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2026.1800407/full][LATTICE
(2026)]] evaluates an immutable action bundle against in-process mutation
and reports successful checks for its tested vectors. That addresses a
different time-of-check/time-of-use surface from two workers concurrently
reading a shared budget. This case models the latter boundary. It is our
proposed Cedar/POO projection, not a reproduction of any paper's runtime.

| Source observation | Proposed Cedar/POO projection | Unverified boundary |
|--------------------+-------------------------------+---------------------|
| A delegated budget cannot be reset at each worker. | =Local= and =Shared= are independent policy owners; =Integrated= C4-composes both. | A trusted host must bind both workers to the same delegation and shared ledger. |
| Per-worker compliance can still exceed a parent-wide cap. | The two-worker trace shows =Local= allowing both sends, while =Integrated= allows only the first. | The example does not discover all descendant workers or enforce a distributed quota itself. |
| Two concurrent checks can both see an unspent shared budget. | Lean shows both stale checks Allow, whereas serialized admission rejects the second proposal. | Cedar evaluates requests; atomic reserve/commit and tool execution remain host duties. |
| [[https://docs.cedarpolicy.com/auth/authorization.html][Cedar skips policies that error during evaluation]]. | =Integrated= overlays the broad permit with both positive budget predicates, so a missing counter cannot leave a valid grant. | A host must still validate complete request context and treat diagnostics as an operational failure. |
| Incident response must stop both workers without rewriting permanent controls. | =Incident= extends one egress veto; =Recovered= removes only that veto. | An external authority determines when the incident is resolved. |

The workers, destination, and budget values in
[[file:SharedBudget.lean][SharedBudget.lean]] are illustrative. The model
checks a trusted =State= supplied to Cedar's request context. A production
host must authenticate worker lineage, validate counter ranges, serialize
decision plus reservation across every worker, bind approval to the exact
tool call, and keep the shared ledger durable. A Cedar Allow from an old
snapshot is not an execution permit after another worker has committed.

* Decision and race matrix

=A= means Allow and =D= means Deny. The default parent-wide cap is one
external send; each worker also has a local cap of one. The separate
same-worker row uses a shared cap of three to isolate the local control.

| POO root | Worker A then B, shared cap 1 | Worker A twice, shared cap 3 | First otherwise valid send during incident |
|----------+-------------------------------+------------------------------+--------------------------------------------|
| =Base= | A, A | A, A | A |
| =Local= | A, A | A, D | A |
| =Shared= | A, D | A, A | A |
| =Integrated= | A, D | A, D | A |
| =Incident= | D, D | D, D | D |
| =Recovered= | A, D | A, D | A |

The =Local= branch leaves the fanout hole; the =Shared= branch leaves the
same-worker hole when the parent has a larger aggregate allowance.
=Integrated= closes both in the serialized model. An already spent shared
budget denies the next proposal without changing state. The named Lean
cases and pre-admission contexts are exported step by step to the official
Cedar Rust authorizer. A worker absent from the bound delegation is denied
before invoking Cedar authorization.

The two missing-field requests expose a Cedar-specific failure mode. With
=Base=, missing =localUsed= still permits a send. If the final root depended
only on budget =forbid= policies, an error in a veto could leave that permit
effective. =Integrated= overlays the permit with both positive budget checks:
missing =localUsed= or =sharedUsed= then yields no satisfied permit and Deny.
The Lean decisions and official Rust decisions agree for both malformed
requests. The intermediate =Local= and =Shared= roots illustrate partial
owners; only =Integrated= is the proposed final deployment root.

The two checks against =S0= each return Allow. The Lean
=staleDoubleCommitExceedsBudget= result deliberately applies both updates
without rechecking and reaches =sharedUsed= of =2=. Under =replay=, which
commits the first decision before checking the second, the decisions are
=[true, false]= and =sharedUsed= of =1=. This finite example exposes the race;
it does not implement a distributed transaction or prove its correctness.

* Composition and proof receipts

| Root | Owner-local edit | Materialized policy bodies | Fresh body work against stated baseline |
|------+------------------+----------------------------+----------------------------------------|
| =Base= | Extend delegated send grant | 1 | 1 |
| =Local= | Extend worker-local budget veto | 2 | 1 vs =Base= |
| =Shared= | Extend delegation-shared budget veto | 2 | 1 vs =Base= |
| =Integrated= | C4-compose both owners and overlay the final permit | 3 | 3 vs =Base= |
| =Incident= | Extend egress freeze | 4 | 1 vs =Integrated= |
| =Recovered= | Remove only the freeze | 3 | 0 vs =Incident= |

Six standalone Cedar revisions contain 15 materialized policy occurrences.
Lean declares five distinct policy bodies and six local edits, including
the final permit overlay and recovery removal. This is a source-structure count, not a performance
measurement. The incident revision adds one fresh body, recovery adds none,
and unchanged certificates are reused when the authorization certificate
is reclosed. Cedar's upstream soundness theorem applies to the resulting
snapshot. The [[file:SharedBudgetExport.lean][exporter]] sends every named
request to the official Rust Cedar authorizer and checks all generated
=.cedar= revisions after rendering and reparsing.
