* Scope and acceptance event

The first executable slice is single-root authorization retirement at a
provider-local protected acceptance event. The root is the independently
authenticated pair =(budgetScope, rootMandateId)=. Scope ownership binds the
principal; an untrusted caller must not select another principal's namespace.
Generation is a root incarnation counter, distinct from principal policyEpoch.
Key rotation increments generation. Retirement is irreversible for that root.
Reauthorization requires a fresh authenticated root incarnation and namespace.

The issuer's root cut and a provider's installed fence are distinct events.
Missing installation evidence means quiescence is unknown. An old ticket can
still be accepted before that endpoint installs the fence. Work accepted before
installation can complete afterward and remains accountable through its exact
provider receipt. No cross-provider global clock is assumed.

* Validation and deployment gates

=just check-agentic-ai-commerce-acceptance= builds Lean, regenerates its JSON,
compares the checked fixture, and executes the independent Rust consumer.
The Rust gate includes acceptance as its own isolated feature profile.
MRR tests exercise fresh acceptance, claim then retirement, rotation, logical
endpoint restart, unrelated root cuts, misbound authority, unknown result and
recovery of a pre-fence accepted request.

A deployment must provide durable root fences, accepted operation/body records,
authenticated updates, scope ownership and endpoint serialization. Loss of
fence state fails closed; default initialization from an old worker snapshot
is prohibited. No database or payment rail is provided by these libraries.

* Recovery boundary retained

| Observation | Allowed action | Fresh permit? |
|-------------+----------------+---------------|
| uncertain conditional claim | recover exact commit receipt | no |
| acknowledged claim, process lost before send | recover committed descriptor and acquire fenced provider ownership | no |
| known non-release / NotSent | retain consumed purchase and report refusal | no |
| provider outcome unknown | query exact original provider and body | no |
| accepted receipt before fence | verify/query same receipt after retirement | no |
| absent or unavailable provider status | retain unknown; never switch provider or operation ID | no |

Resumable release uses the [[file:Recovery.org][fenced ownership protocol]]: the endpoint rejects
an earlier owner at protected acceptance. Deployment durability and eventual
completion remain external; global root quiescence, AP2 conformance and settlement
are not established by the pure model.
