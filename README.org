#+TITLE: Cedar POO Spec
#+OPTIONS: toc:nil

*Cedar POO Spec* is the formal integration of
[[https://github.com/cedar-policy/cedar-spec][cedar-spec]] with [[https://github.com/tao3k/lean-poo][Lean-POO]]. It studies prototype-oriented
composition and incremental proof reuse against Cedar's upstream Lean
specification.

* Repository boundary

- =cedar-spec= remains the authority for Cedar expressions, evaluation,
  typechecking, extensions, and soundness. This repository depends on
  upstream definitions rather than forking them.
- Lean-POO owns generic C4 resolution, prototype and object composition,
  patches, proof objects, obligations, dependency tracking, invalidation,
  refinement, and certificate closure.
- This repository owns the Cedar-specific adapter, formal integration
  examples, and reproducible proof-reuse measurements.
- Domain policies and product extensions belong in separate downstream
  repositories. They are not part of Lean-POO or this specification
  adapter.

* Planned layers

| Layer | Responsibility |
|-------+----------------|
| Cedar adapter | Represent upstream Cedar definitions through Lean-POO abstractions without changing Cedar semantics. |
| Composition examples | Exercise overrides and proof obligations on small Cedar-derived cases. |
| Evaluation | Measure proof reuse, change impact, and repair effort on pinned upstream revisions. |

Agent delegation, device trust, temporal authorization, and healthcare
policy are possible downstream studies. They do not define this library's
semantics.

* Initial milestones

1. Pin compatible upstream =cedar-spec= and Lean-POO revisions.
2. Implement a small adapter for Cedar expressions and evaluator artifacts.
3. Compose a minimal Cedar-derived extension and record its proof
   obligations.
4. Compare reused and invalidated proofs after an override.
5. Report reproducible measurements and the exact revisions used.

* Status

The first executable adapter is in
[[file:CedarPooSpec/Evaluation.lean][CedarPooSpec/Evaluation.lean]]. It stores upstream Cedar expressions,
requests, entities, and evaluation results in a typed Lean-POO proof
object. Its obligation states that the stored result equals Cedar's own
evaluator output.

The adapter declares an exact dependency footprint. A label-only patch
reuses the existing evaluation certificate. An expression override writes
the new expression and upstream evaluation result, reports the changed
dependencies, and closes the pending certificate. The runnable
[[file:Examples/Evaluation.lean][evaluation example]] shows both paths.

extensions, or measure reuse on a large proof corpus.
