#+TITLE: Cedar POO Spec
#+OPTIONS: toc:nil

*Cedar POO Spec* is the formal integration of
[[https://github.com/cedar-policy/cedar-spec][cedar-spec]] with [[https://github.com/tao3k/lean-poo][Lean-POO]]. It studies prototype-oriented
composition and incremental proof reuse against Cedar's upstream Lean
specification.

* Repository boundary

- =cedar-spec= remains the authority for Cedar expressions, evaluation,
  typechecking, extensions, and soundness. This repository depends on
  upstream definitions rather than forking them.
- Lean-POO owns generic C4 resolution, prototype and object composition,
  patches, proof objects, obligations, dependency tracking, invalidation,
  refinement, and certificate closure.
- This repository owns the Cedar-specific adapter, formal integration
  examples, and reproducible proof-reuse measurements.
- Domain policies and product extensions belong in separate downstream
  repositories. They are not part of Lean-POO or this specification
  adapter.

symbolic compiler and a concrete counterexample replayed by Rust Cedar.
[[file:docs/rfc/0005-cedar-replay-receipts.org][RFC 0005]] defines content-bound
Rust Cedar replay receipts for checked Lean manifests.
[[file:docs/rfc/0006-schema-bound-cedar-replay.org][RFC 0006]] adds an explicit
Lean-to-Cedar schema projection, schema-bound replay API, and a schema-only
evolution receipt for unchanged concrete authorization inputs.
[[file:docs/rfc/0007-poo-dispatch-boundary.org][RFC 0007]] defines the
construction-time boundary for Lean-POO multiple dispatch across independently
extensible policy profiles.

It also includes a trusted-network revision that checks Cedar IP extension

The [[file:Examples/Language/README.org][language example]] checks concrete
Cedar scope and pattern syntax across a POO overlay, plus all pinned Cedar
extension functions and values. The
[[file:Examples/Enterprise/README.org][enterprise examples]] cover delegated
procurement approval, compound payment release, and AI agent delegation,

[[file:Examples/Enterprise/Agent/Session/README.org][bounded agent session]]

[[file:Examples/Enterprise/Agent/Fanout/README.org][shared budget fanout]]

[[file:Examples/Enterprise/Agent/Department/README.org][cross-department synthesis]]

[[file:Examples/Enterprise/Vehicle/README.org][vehicle examples]] include

* Verification

=just lean-poo-api= lists the public modules from the locked LeanPOO
dependency. =just lean-poo-api-find 'Multimethod.register'= searches its Lean
declarations and uses the same revision that Lake builds for this project.

=just check= runs the complete local gate. Its smaller entrypoints are
=check-docs=, =check-lean=, =check-tests=, =check-rust=, =check-cedar-artifacts=,
=check-mission-comparison=, and =check-delta=. CI gives documentation, Lean,
Rust, Cedar conformance, and authorization delta separate jobs. The latter
two start after the Lean and Rust jobs and restore their Lake and Cargo build
caches. Lake cache identity includes the toolchain, dependency manifest, and
Lean sources; the Cargo cache includes the Rust compiler and manifests.
The =check-replay-receipts= entrypoint checks the agent-payment diagnostic
replay output. =check-schema-bound-receipts= checks the corresponding
well-typed payment operations through Cedar's strict schema validation.
=check-schema-bound-scenarios= covers cross-tool data flow, the trusted
network IP extension, and country-specific tags and Action inheritance
under the same official Cedar boundary.

* Status

The executable adapters are in
[[file:CedarPooSpec/Evaluation.lean][Evaluation.lean]] and
[[file:CedarPooSpec/Validation.lean][Validation.lean]]. They store upstream
Cedar expressions, requests, entities, policies, type environments, and
computed results in typed Lean-POO proof objects. Their obligations bind
those results to Cedar's own evaluator and policy typechecker.

Each adapter declares an exact dependency footprint. A label-only patch
reuses the existing evaluation certificate. An expression override writes
the new expression and upstream evaluation result, reports the changed
dependencies, and closes the pending certificate. A policy override
does the corresponding work for typechecking.

[[file:CedarPooSpec/Composition.lean][Composition.lean]] pairs these
independent certificates and adds an explicit alignment obligation between
the evaluated expression and the checked policy. A change on one side
reuses the other side's certificate, while alignment becomes pending.
[[file:Examples/Composition.lean][Composition.lean]] prints the exact
dependency and repair report through Lean-POO's public Debug API.
[[file:CedarPooSpec/Soundness.lean][Soundness.lean]] transports the upstream
Cedar typechecker soundness theorem through the certified snapshot. It
requires Cedar's well-formed environment premise and a successful typed
result; no replacement soundness argument is invented here.
It also transports =validation_is_sound= for a whole policy set through
four explicit Cedar validation obligations. The theorem retains Cedar's
documented runtime-error cases; it is not an unconditional allow or
error-free claim.
[[file:CedarPooSpec/Slicing.lean][Slicing.lean]] combines that certificate
with Cedar's level validation and transports the upstream response
equality theorem for request-relative entity slices.

The Lake manifest pins =cedar-spec= and Lean-POO. After deliberately changing
a pinned revision in =lakefile.toml=, =just sync= refreshes the lockfile and
runs the complete checks. It does not select an upstream revision on its own.
This slice does not yet
provide domain extensions or measure reuse on a large proof corpus.
