#+TITLE: Cedar POO Spec
#+OPTIONS: toc:nil

*Cedar POO Spec* is the formal integration of
[[https://github.com/cedar-policy/cedar-spec][cedar-spec]] with [[https://github.com/tao3k/lean-poo][Lean-POO]]. It studies prototype-oriented
composition and incremental proof reuse against Cedar's upstream Lean
specification.

* Repository boundary

- =cedar-spec= remains the authority for Cedar expressions, evaluation,
  typechecking, extensions, and soundness. This repository depends on
  upstream definitions rather than forking them.
- Lean-POO owns generic C4 resolution, prototype and object composition,
  patches, proof objects, obligations, dependency tracking, invalidation,
  refinement, and certificate closure.
- This repository owns the Cedar-specific adapter, formal integration
  examples, and reproducible proof-reuse measurements.
- Domain policies and product extensions belong in separate downstream
  repositories. They are not part of Lean-POO or this specification
  adapter.

* Features

[[file:docs/rfc/0001-certified-authorization.org][RFC 0001]] defines the
implemented authorization and entity-slicing certificate contract.
[[file:docs/rfc/0002-policy-module-composition.org][RFC 0002]] defines
policy module edits and conflict handling.
[[file:docs/rfc/0003-cedar-language-export.org][Cedar language export]]
connects compiled Lean policy modules to the official Rust authorizer through
Cedar's public JSON policy-set format.
The [[file:Examples/Governance/Policies/expanded.cedar][final ticket-sharing policy]]
is also committed as readable Cedar language syntax.
[[file:docs/rfc/0003-cedar-language-export.org][RFC 0003]] shows the downstream
Lean extension and Rust deployment interface.
The executable
[[file:Examples/Scenarios/README.org][tenant document scenario]] shows why
overlay, extend, and remove are all needed during an authorization migration.
The [[file:Examples/Health/README.org][health example]] connects a clinical
emergency-access diamond to published EHR studies and HL7 guidance.
The [[file:Examples/Governance/README.org][governance example]] uses a
source-grounded attestation revision to show policy provenance, local
invalidation, and certificate reuse across C4 composition. It also includes
a ticket-sharing template revision based on Cedar's published design pattern.
It also includes a trusted-network revision that checks Cedar IP extension
values and a narrower network veto through the official Rust authorizer.
The [[file:Examples/Language/README.org][language example]] checks concrete
Cedar scope and pattern syntax across a POO overlay.

| Feature | Implemented contract |
|---------+----------------------|
| Cedar adapters | Store upstream evaluation and typechecking results in typed Lean-POO proof objects. |
| Composition | Track alignment and preserve unaffected certificates across overrides. |
| Authorization | Transport Cedar's policy-set and response-level soundness theorems. |
| Entity slicing | Certify equality of full and request-relative sliced authorization responses. |
| Policy modules | Compile C4-ordered extend, overlay, and remove edits into Cedar policies; reject ambiguous edits and retain an edit trace and policy provenance. |
| Policy revision | Compare compiled policy bodies by ID; compose per-policy proof objects for fresh bodies and reuse unchanged bodies under the same schema. Reclose all dependent premises after schema changes. |
| Runtime validation cache | Reuse any identical policy body in a Cedar-validated baseline, including after reordering; prove the incremental result equals Cedar's full validation result. |
| Template revisions | Re-link through upstream Cedar, validate only changed materialized bodies, and distinguish link errors from policy validation errors. |
| Cedar language export | Convert supported materialized Cedar policies, entities, and requests to the public JSON formats; reject unsupported abstract syntax; compare Lean authorization receipts with the Rust Cedar engine. |
| Reuse probe | Check dependency selection across 10,000 indexed evaluator obligations. |

Agent delegation, device trust, temporal authorization, and healthcare
policy are possible downstream studies. They do not define this library's
semantics.

* Status

The executable adapters are in
[[file:CedarPooSpec/Evaluation.lean][Evaluation.lean]] and
[[file:CedarPooSpec/Validation.lean][Validation.lean]]. They store upstream
Cedar expressions, requests, entities, policies, type environments, and
computed results in typed Lean-POO proof objects. Their obligations bind
those results to Cedar's own evaluator and policy typechecker.

Each adapter declares an exact dependency footprint. A label-only patch
reuses the existing evaluation certificate. An expression override writes
the new expression and upstream evaluation result, reports the changed
dependencies, and closes the pending certificate. A policy override
does the corresponding work for typechecking.

[[file:CedarPooSpec/Composition.lean][Composition.lean]] pairs these
independent certificates and adds an explicit alignment obligation between
the evaluated expression and the checked policy. A change on one side
reuses the other side's certificate, while alignment becomes pending.
[[file:Examples/Composition.lean][Composition.lean]] prints the exact
dependency and repair report through Lean-POO's public Debug API.
[[file:CedarPooSpec/Soundness.lean][Soundness.lean]] transports the upstream
Cedar typechecker soundness theorem through the certified snapshot. It
requires Cedar's well-formed environment premise and a successful typed
result; no replacement soundness argument is invented here.
It also transports =validation_is_sound= for a whole policy set through
four explicit Cedar validation obligations. The theorem retains Cedar's
documented runtime-error cases; it is not an unconditional allow or
error-free claim.
[[file:CedarPooSpec/Slicing.lean][Slicing.lean]] combines that certificate
with Cedar's level validation and transports the upstream response
equality theorem for request-relative entity slices.
