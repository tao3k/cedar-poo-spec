* Banking tool ownership

[[file:BankingToolOwner.lean][BankingToolOwner]] owns one Cedar permit slot for a banking line of
business and its selected Gateway actions. =introduce=, =revise=, and
=withdraw= expose the slot's Lean-POO edits. The
[[file:../../../Examples/Enterprise/AWS/FinancialServices/MultiAccountBanking/README.org][multi-account banking example]] uses separate Retail, Transaction, and
Lending objects; its incident revision narrows only Transaction's actions.
[[file:BankingToolProfile.lean][BankingToolProfile]] gives one owner a typed action slot and an inherited
computed owner slot. Its [[file:BankingToolProfile.org][adjacent documentation]] explains how a pause and
recovery derive from the same parent without changing the other LOB owners.
The published tool names, customer identities, cross-account credentials,
and data-plane checks remain with the example or a consuming application.

* Controller payment release

[[file:ControllerRelease.lean][ControllerRelease]] owns a controller permit slot. Its broad grant can
be strengthened in place with a matched-payment requirement and either a
decimal amount threshold or senior-controller membership. The
[[file:../../../Examples/Enterprise/Payment/README.org][payment release example]] composes this owner with independent duties,
risk, and legacy-retirement branches. The application chooses the decimal
threshold and authenticates payment attributes, actor membership, and the
effectful transfer.

* Insurance claims summary

[[file:ClaimSummaryVeto.lean][ClaimSummaryVeto]] owns one forbid slot for a claims-summary action when
the principal satisfies a supplied policyholder condition. The
[[file:../../../Examples/Enterprise/AWS/FinancialServices/LakehouseGateway/README.org][insurance lakehouse example]] supplies its AgentCore Gateway action and
Cognito group projection, then composes the insurance rule with independent
Lakehouse location controls. The public object neither assumes Cognito nor
imports an AWS module.

* Agent commerce and payment

[[file:AgentCommerce.lean][AgentCommerce]] owns bounded mandate admission and cumulative purchase
reservation. [[file:AgentCommerceDelegation.lean][AgentCommerceDelegation]] checks each child grant against its exact
parent. [[file:AgentCommerceCredential.lean][AgentCommerceCredential]] binds a credential to one reserved purchase,
and [[file:AgentCommercePayment.lean][AgentCommercePayment]] maps that purchase to a public =PaymentOperation=
using a canonical HKD cents profile. These modules are part of the public
Lean library. The [[file:../../../Examples/Enterprise/Agent/Payment/AgentCommerceResearch.org][research scenario]] and [[file:../../../Tests/Enterprise/Agent/Payment/AgentCommerce.lean][regressions]] consume them.
The optional Rust signature verifier is a public crate module behind the
=mandate-offer-signatures= Cargo feature; see [[file:../../../rust/src/README.org][Rust feature boundaries]]. The Host must
authenticate and map the verified Rust fields into these Lean structures.
[[file:AgentCommerceProjection.lean][AgentCommerceProjection]] emits public Lean claims without =verified=; the optional
=lean-mandate-offer-projection= Rust feature compares those claims with live
verified mandate and offer values. =just check-agent-commerce-projection=
exercises the cross-language mapping with signed synthetic inputs. The Host
must also check time, key status, policy, and revocation before setting
=verified=. The optional Rust =agent-commerce-admission= reference performs those dynamic
checks for signed root mandates, narrower signed child chains, and merchant
offers with a Host-supplied clock and policy evaluator. It compares each
verified mandate to the complete Lean lineage. Its registry and revocation
state are process-local; durable shared-budget reservation and effect receipts
remain separate work.

* Boundary

=Vertical/FinancialServices/= holds finance-specific reusable controls.
=Platform/AWS/= holds AWS AgentCore projection helpers; finance controls
do not import that platform adapter. =Data/Lakehouse/= holds the general
location boundary. A downstream AWS financial-services profile selects all
three layers. Scenario records, source quotations, policy artifacts, and
complete workflows remain in =Examples/=.
