#+TITLE: LeanPOO typed industry objects and contracts

* Dependency and authority

The library and lockfile pin [[https://github.com/tao3k/lean-poo/pull/13][LeanPOO PR 13]] at
=3c9dec0f662bf5ea51ef0394cbaac36723accf46=. This is a pinned research-branch
snapshot, not a claim that PR 13 has merged. SPEC retains Lean 4.34.1 and its
existing Cedar revision; no unrelated dependency upgrade is included.

Industry models use the existing typed object and Contract systems. LeanPOO
owns typed declarations, C4 inheritance, final-self computation, contract
diagnostics and refinement. SPEC supplies industry fields and predicates, and
Cedar owns policy/schema validation and authorization. Host facts remain a
separate admission responsibility.

* Executable cache and index use

The dependency snapshot above was checked against the live PR head for this
stage. Its [[https://github.com/tao3k/lean-poo/actions/runs/41300497739][17-job exact-revision CI]] passes. Relative to the preceding
=3abffcaa7728cebd1ff0ee6c9bf6e939b7175e26= pin, the delta chiefly adds
boundary theorems and examples. C4 Prepared, Object Memo and Functional ContextSlot
implementations are unchanged. Updating the pin is required for API/proof
alignment; it is not itself an algorithmic speedup claim.

| Actual SPEC owner / caller | Executable POO mechanism | Alignment boundary |
|----------------------------+--------------------------+--------------------|
| =PolicyModules.Model.compilePlanPrepared=, then =compileSelected= | =Plan.compileMemo= builds =CompiledPlan.effective : Std.DHashMap=; =CompiledPlan.resolve= performs the keyed method lookup | =compilePlanPrepared_eq= and =CompiledPlan.resolve_sound=; Cedar edit intent/provenance still execute |
| =Functional.Compilation= and =PolicyModules.Model.prepareC4= | Graph-owned =C4.Prepared= node index, shared ancestor preparation and per-root thunks | =prepareC4_current= and =Prepared.at_eq=; source revision cannot substitute another graph |
| =Functional.Reuse.RootSlot= | =Requirements.ContextSlot= retains exact Program/root dependency data | =ContextSlot.consume_value=; =RootSlot.read_value= retains full success/error outcomes |
| Lean =Transport.Case.EntitySlot= | Same =ContextSlot= over the complete semantic Entities context | =EntitySlot.read_value=, with at most one retained context; no global entity cache |
| Nine =Functional.ObjectProfile= families | Existing POO Dataflow template schedules and materialized instances | Existing actual field, source, inventory and Contract/refinement proofs |

Thus absence of a local function named index does not imply absence of a runtime
index: the policy compiler reaches the POO method hash table through compileMemo
and resolve. Retained data stay in their existing object/Program owners.

=Prototype.RepresentationIndex= also contains finite semantic models for the
Gerbil sparse ordered-index/storage contract. Importing those definitions is
not equivalent to selecting an executable fast Lean or Rust backend. Use the
actual executable APIs above and their source-bound laws, rather than introducing
another registry, wrapper or cache to reproduce a specification-level index.

Cedar SDK Schema/Entities first parsing executes in Rust through public SDK
entrypoints. A Lean object cache does not automatically eliminate that independent
admission boundary. The current SDK optimization reuses complete source wire
already owned by immutable Rust source objects, preserving strict validation,
independent replay and exact original rejection diagnostics. See the current
[[file:native-shared-plan-rendering.org][native performance and resource audit]] for measured results and limitations.

* Complete materialized-object migration

All nine families use =Object.Dataflow.Instance= through the shared
=Functional.ObjectProfile= carrier: Policy, banking, controller release, source,
location, protection, disclosure, handoff and lineage. Typed =Expr.need= and
Applicative composition expose each derived field's actual dependencies. The
banking/source/control/channel constructors preserve their original captured
initial records, and read exactly the final-self fields used before migration.
Contracts still compare actual inputs and derived results, so a forged template
or projection does not gain admission.

The source-aligned POO Template compiles C4-selected inherited fragments, a
checked dependency schedule and executable resolver/read-set tables. Instance
values are materialized through the existing ConstructionCache. Dependency-equal
revision may reuse a schedule, but not old instance values. =materialized_read=,
=materialized_inventory= and =materialized_source= are additional universal laws;
the existing provider/Contract/admission laws remain in the standard-axiom audit.

The complex medical lineage Case keeps independently built families, inherited
defaults, delayed super, strict duplicate checks and original source ordering.
Every family's native guard also checks the actual materializer work record:
one evaluation per graph key, including shared dependencies, and exact reflected
inventory. Typed missing/forged and factory-retirement controls remain active.

The inspectable Computation family lives in Type 1. Diagnostics are polymorphic
in the object carrier; Type 0 observations use the standard heterogeneous
=Option.bind= and =Except.bind=. No erased-value wrapper, cast or second evaluator
is added. Existing =PolicyModules= composes literal policy/tombstone slots without
self dependencies; that separate C4 edit/provenance protocol is preserved. All
its consumers remain in the full Case and Rust replay gates.

* Static and dynamic boundaries

The dependent =Value : Key → Type= prevents putting an entity identity in a
purpose slot, or a policy in a threshold slot. It does not establish that a
String is a positive decimal or a nonempty industry purpose. Those predicates
belong to the reusable Contract refinement. No second type checker, subtype
inference engine, contract compiler or policy evaluator is implemented here.

Contract views use cached =slotNames= and actual typed reads. The universal
=materialized_inventory= law equates that exact inventory with =LeanPoo.allSlots=
of the retained C4 plan. Presence checks
erase values to Unit because their carrier types are already statically fixed;
whole-object predicates read the original typed values. =isObject= and
=prototype= are true for this statically indexed carrier; they do not claim
runtime ancestry authentication of arbitrary wire values. Missing slots and
overridden projections still fail the inventory/alignment checks.

=policy?= exposes no policy unless =diagnose contract profile [] = []=.
=policy_requires_contract= proves this for all profile values. Raw =Object.read=
remains an inspection API; it is not contract admission. A further contract
refinement cannot remove an inherited refusal, by LeanPOO's existing theorem.
Constructing a typed object or satisfying this contract still does not authorize
a request or validate an arbitrary Cedar schema.

* Industry consumers

The shared [[file:../CedarPooSpec/Functional/README.org][Functional capability layer]] now carries these consumers through
preparation, checked policy data, publication and actual request evaluation.
Their Type/Contract checks feed the model; their Cedar evidence feeds the
Functional consumer. They do not stop at typed profile construction.

The prior-authorization Case now builds the memory channel as a typed child of
the verification channel, overriding only industry input slots and inheriting
channel/policy computation. Its existing privacy, delegation, removal and
incident roots continue to consume checked policies.

The payment Case obtains its controller control/policy from the checked typed
profile. A child lowers the threshold from 500 to 200 while retaining controller
and senior slots. Its =Restricted= root is used in Cedar authorization tests:
the ordinary controller loses the 250 payment permission, the senior controller
retains it, and the original =Integrated= root remains unchanged.

* Cleanup and verification

=PolicyModules= has one source-identity gate for retained schemas and objects,
and one root-plan selector for compilation and diagnostics. Diagnostics no
longer instantiate a memoized object merely to read its plan. The staged-schema
path is retained for extensions of older roots. Unnecessary Builder/Memo and
Object.Debug imports are removed where the public owner module already supplies
the API or the import is unused. No end-to-end performance claim follows.

[[file:../Tests/Language/LeanPooAlignment.lean][LeanPooAlignment]] checks warm-object/schema invalidation after raw source edits,
old-root retention, tombstones and the distinction between object construction
and Cedar edit admission. [[file:../Tests/Language/VerticalProfiles.lean][VerticalProfiles]] checks independent expected channel
and policy values, inherited settings, actual Cedar decisions, malformed/zero/
negative thresholds, empty purpose, forged derived policy and inherited refusal.

existing layer check must keep library/Production separate from Examples.
The full GitHub CI additionally qualifies existing Rust conformance, exported
