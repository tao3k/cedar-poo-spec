** Lean: eliminate structural work on same-owner cache hits

The original generic =ContextSlot.read= invoked =DecidableEq= even when the
caller passed the very same immutable context. For Cedar Entities, generated C
allocated two comparison closures before traversing the semantic map. Reusing the
payload alone did not remove this hit-path work.

The shared implementation now uses Lean's standard checked =withPtrEqDecEq=.
Same-owner hits return retained dependent data directly; independently allocated
contexts still execute the original structural comparison. No new unsafe
primitive, axiom, mutable identity authority or global cache is introduced.
=ContextSlot.read_reference= proves equality of the entire original structural
reference tuple: snapshot, next slot and reuse flag. Existing =read_value=,
=consume_value=, rebinding and replacement proofs compile unchanged. Its axiom
audit reports only standard =propext=.

The actual Cedar generated C confirms the address comparison precedes the two
EntityUID/EntityData closure allocations and map equality call. The unequal-owner
branch contains the original structural decision once. This is consumer-level
code-generation evidence, not merely importing a faster upstream API.

** Rust: cache the SDK result and retire its intermediate representation

The preceding EntitySource owner lazily retained full JSON during source-table
uniqueness. Every encoding survived until the whole catalog owner retired,
even after the one-slot SDK Entities cache already held the prepared result.
This accounted for the prior approximately 80 KB higher requested peak.

EntitySource now shares the immutable Value directly. Source-table uniqueness
fingerprints its ordered structure without allocating encoded JSON, then uses a
standard HashSet with complete exact source equality. Hash collisions cannot
accept duplicates or reject distinct sources. The index borrows Values and
retires after checking. Expected hashing work is linear in source payload;
collision cases still require full comparisons and are not claimed constant time.

Only the SDK preparation miss encodes an entity source. That String is scoped to
=Entities::from_json_str= and drops before a diagnostic fallback. The expensive
parsed SDK object stays in its existing one-slot owner. Schema wire retains its
existing multi-consumer sharing. This is a lifetime decision for each actual
representation, rather than caching every derived value for the catalog lifetime.

Signed zero, numeric representation and object iteration order retain exact wire
identity. Tests compare all 49 numeric pairs against actual encoding, and all 49
source pairs with every fingerprint forced to collide. Core passes 10 tests;
Runtime passes 57 with one pre-existing ignored full-catalog oracle, executed
explicitly by the complete gate. No ASP criterion is disabled: its initial
rejection of a hand-written collision-bucket scan is retained; the final standard
HashSet implementation passes the original algorithm gate.

SDK rejection still uses the original Value path for exact original diagnostics.
Both physical diagnostic-reparse counters remain visible; valid actual-catalog
samples require zero. Lean proofs establish typed/source/Contract laws; SDK
compatibility remains executable differential evidence, not a claim that the
foreign SDK is covered by the Lean theorem.

* Pre-main long tail: current evidence and remaining boundary

The fixed diagnostic stage retains 24 children: six per Lean/Rust and
copy/hardlink mode, with two first-path cohorts and their four warm repetitions.
All full outputs, image identities, bounded clock intervals, stderr byte coverage
and stopped resource observers are checked. Three near-exit task reads are
unavailable and retained explicitly; available thread reads have no errors or
truncation. Loader arrivals are external upper bounds, not child write times.

| Mode | First new path pre-main ms | Second new path pre-main ms | Four warm repeats ms |
|------+----------------------------+-----------------------------+----------------------|
| lean-copy | 1290.149 | 1514.248 | 42.712 / 41.405 / 41.546 / 41.254 |
| lean-hardlink | 739.965 | 737.380 | 43.668 / 41.873 / 41.609 / 42.126 |
| rust-copy | 517.282 | 357.792 | 4.261 / 4.181 / 4.353 / 4.294 |
| rust-hardlink | 372.496 | 86.923 | 4.464 / 4.345 / 4.356 / 4.457 |

Lean's two hardlink paths use the same inode yet both retain long initial waits.
Rust's second hardlink path also retains an approximately 80 ms stationary wait
in this stage, whereas the preceding stage had a short second path. Thus inode
reuse is not a sufficient guarantee for either runtime. Long samples precede
first observed dyld output while the initial user thread is sampled waiting and
CPU/fault/context counters remain stationary. Subsequent repeated-path Lean
pre-main work is approximately 41-44 ms, Rust approximately 4 ms; algorithm and
initialization work remain distinct from the long pre-loader interval.

Eight read-only exact-owned PID/path/time OS-log queries return zero events;
this is not evidence that a particular service did not execute. The public
task-info observation does not expose the exact kernel wait event.
No exclusive filesystem, signature-validation service, loader or Lean-runtime
cause is inferred from these correlations. No security settings or limits change.
All historical failures, non-wins and same-inode counterexamples stay retained.

and ContextSlot hot/cold images are identical. Toolchain/stdlib remain installed.

The next complete pass should prioritize the measured remaining owners:

1. Reduce intermediate Entity wire buffer growth without retaining complete
   strings for the catalog lifetime. Preserve exact JSON identity/collision tests,
   zero diagnostic reparses on valid inputs, all source/slot/error laws and the
   measured peak reduction; compare total allocation requests as well as peaks.
2. Optimize first SDK preparation at its actual boundaries. Candidate median
   revision preparation is about 47.8 ms, schema preparation 30.9 ms and request
   preparation 29.2 ms (nested accounting, not additive totals). Exact-source
   text parsing/normalization and request conversion dominate more than the
   approximately 4.5 ms Entity preparation. Reuse parsed dependencies only inside
   their actual source/schema owner; independent revision validation and both
   authorizers must still run. Lean source serialization has no stable gain yet.
3. Keep initialization and the pre-loader wait separate. Existing evidence
   narrows where waiting occurs, but a precise kernel event remains unresolved.
   Keep the same fixed cold-build and paired whole-entry controls; preserve every
   non-win rather than changing timeouts, workloads or startup accounting.

Acceptance for another algorithm change remains the same complete nine-family,
51-entry catalog with types, Contracts, original proofs, original SDK oracle and
full Rust replay; native Lean/Rust measurements, ordinary process/resource
observations and exact-source CI are separate receipts. PR #8 stays unmerged.
