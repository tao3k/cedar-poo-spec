** Real source publication

The existing SourcePool now holds an optional recent index. Publishing compares
the complete snapshot wire with that entry before hashing the whole source.
A missing, stale or forged hint takes the original indexed fallback; successful
publication updates the same owner's cursor. There is no parallel source owner,
registry or decision cache. This reduces repeated hash preparation for adjacent
Cases sharing a source; it does not claim to eliminate source construction or
all source traversal. The universal =publishSnapshot_recent= theorem proves the
checked hit preserves the pool and inventory. Missing-index and stale-source
controls preserve fallback behavior. Proofs use only the three standard Lean
axioms; source/frame/value and original Contract obligations remain unchanged.

** SDK normalization through public typed APIs

Policy normalization now uses Cedar SDK 4.12 public PST APIs: =to_pst=,
linked-policy materialization, =Policy::from_pst= and =to_cedar=. It removes the
intermediate JSON Value encoding/decoding used solely for normalization.
No private AST, dependency or feature change is involved. Every original text
still parses independently; source-keyed reuse, strict schema validation,
request preparation and both authorizers retain their existing boundaries.

The previous JSON route remains an independent test oracle: 11 policy texts in
text and JSON forms cover formatting, comments, Unicode, annotations, number
boundaries, collections, patterns, IP and decimal; real template links test two
principals, and an allow/deny mutation is a negative control. Runtime checks pass
55 tests with one pre-existing ignored test and no additional ignored cases.

* Same-PID pre-main narrowing and remaining uncertainty

One separate fixed six-child cohort combines the existing thread-state observer
with owned-image dyld loader/initializer logging. In its two fresh-file children,
stderr readers are ready after 3.652 / 3.201 ms, but the first owned-image loader
line arrives after 1210.459 / 1085.353 ms. Before that, 170 / 153 samples observe
the initial handle waiting, ending at 1202.625 / 1080.072 ms, with stationary task
CPU, faults, page-ins and resident bytes. Pre-main lasts 1272.784 / 1155.360 ms.
Four repeated starts have pre-main 42.598 / 41.703 / 41.441 / 41.073 ms, first
loader arrival 2.230-2.715 ms and no sampled initial waiting plateau.

The reader was available early, and the long wait precedes the first observed
loader activity. Arrival is an upper bound, not the child's write timestamp or
an exact loader-entry timestamp. Samples do not prove continuous waiting and
public thread handles are not unique thread identities. All six complete
outputs, clocks, stderr accounting and stopped observers validate.

Exact owned PID/path/short-window OS log queries return zero events. This is not
proof that no assessment occurred. Noninteractive off-CPU DTrace requires an
administrator password; no security, signing, SIP or logging setting was changed.
The precise kernel wait event or responsible service remains unresolved.
The evidence supports an initial non-CPU waiting interval, not attribution to a
specific service, filesystem, runtime function or Cedar algorithm.
