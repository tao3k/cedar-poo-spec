* Shared POO algorithm audit and implementation

The existing =CompiledPlan.effective : Std.DHashMap= still supplies actual keyed
method lookup. Graph-owned =C4.Prepared= still owns node/ancestor/root preparation.
This stage changes the shared context algorithm and source serialization rather
than adding another object registry, memo table, equality authority or runner.

** Equal independent owners previously paid repeatedly

A hit originally retained the old context owner. Repeatedly requesting a new but
structurally equal immutable owner therefore repeated full equality on every read.
The slot now adopts the requested context index and retains its certified data;
the next same-owner read takes the standard checked identity shortcut. For a
length-n independent context followed by r repeated reads, comparison work becomes
one full comparison plus identity hits, instead of r full comparisons. Storage
remains zero or one context/snapshot pair; no second context is retained by the
slot. A snapshot can itself retain other immutable data, as before.

=ContextSlot.read_reference= compares the entire snapshot, next slot and hit flag
against an arbitrary reference DecidableEq. Owner adoption is propositionally
equal to the old slot. Factory family, joint Claim, first errors, eviction and
consumer execution are unchanged. All prior read/consume/rebind laws compile.
Read and consume are inline so projected consumers can eliminate intermediate
tuples; the caller still executes its current output constructor on each read.

** Proof decision code had an expensive negative path

The first candidate's independent-equal path improved, but misses still cost
about 30 ms. A separate uncached control using the same certified factory and
alternating contexts cost about 2.8-3.0 ms. This rules out factory work alone as
an explanation for the earlier miss cost.

Inspection of the measured Lean 4.34.0 native List DecidableEq image shows the
recursive =List.hasDecEq= call before the head decision. A changed first element
still traversed the long tail. No universal claim about all Lean versions or all
decision procedures follows from that image.

The existing shared APIs now accept computational =BEq Context= and its
=LawfulBEq Context= proof. The standard checked =withPtrEqDecEq= uses the lawful
Boolean decision on distinct owners; exact kernel equality supplies the dependent
cast. Native List BEq checks the head before advancing to its tail. The change
improves negative-prefix work without treating a fingerprint or unchecked Boolean
as equality authority. A LawfulBEq proof establishes semantics, not arbitrary
user-comparator cost bounds.

All fourteen shared context modules propagate that comparison and law: base
read/consume, projections, pullbacks, observations, borrowed views, dictionaries,
shared views, retargeting, analysis, constraints, requests, Contract consequence
and Contract joins. Generic clients with only DecidableEq can still obtain the
standard Boolean fallback; performance-sensitive owners select their actual
computational instance. Cedar selects a local lawful Map comparison through the
public ordered =Map.toList= view. Its proof holds for all represented maps, not
only well-formed production inputs, and introduces no global Cedar instance.

No custom unsafe primitive or axiom is introduced. The formal paper re-audit
preserves all 45 requirement statuses. Source equality and standard identity
premises do not prove whole-machine/Scheme refinement or universal speedup.

* Exact-size Rust source encoding

The prior temporary-wire lifecycle removed catalog-long Entity retention but
added geometric String growth at each actual SDK miss. The existing generic
=JsonSourceIdentity.encode_source= now serializes the immutable Value once to a
stack-only counting writer, allocates an exact-size Vec, serializes into it and
checks UTF-8 before transferring ownership to String. The counting pass allocates
no output; it uses the same standard serializer, including escaping, signed zero,
numeric representation and object ordering. There is no hand-written JSON codec,
new metadata cache, pooled owner or retained Entity wire.

This applies to both actual Entity SDK misses and existing shared artifact/source
encodings. Schema/policy wire keeps its established multi-consumer ownership;
Entity wire still drops on parse completion before original-diagnostic fallback.
Parsed SDK Entities stay in their original schema-bound one-slot owner.

The extra traversal and UTF-8 validation can cost CPU; lower allocator requests
alone are not a whole-entry speedup claim. Core passes 11 tests; Runtime passes
57 with one pre-existing ignored full-catalog oracle executed explicitly by the
complete gate. The new bytewise oracle covers null/empty objects, escaping,
Unicode, signed zero, large integers and a 1024-entry nested array. Original
numeric 49-pair and forced-collision 49-pair source tests remain. All exact SDK
rejection strings, failure-state retention and independent Value-route replay
remain active; valid actual-catalog diagnostic reparses must both stay zero.
